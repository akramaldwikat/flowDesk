# FlowDesk — إدارة مترابطة لعمليات الأعمال

**مشروع تجريبي مستقل. جميع المؤسسات والأشخاص والسجلات خيالية.**

اكتملت النواة التشغيلية وتم التحقق منها محليًا. تمت الموافقة على نشر المصدر، بينما تبقى الاستضافة محظورة دون موافقة مستقلة. هذا عمل أصلي لعرض المهارات، وليس مشروع عميل أو دليلًا على استخدام إنتاجي. هذه نسخة بديلة جاهزة للمراجعة، ولم تُطبّق على موقع الأعمال.

## نظرة عامة ومشكلة الأعمال

يربط FlowDesk الأعضاء والعملاء والمشاريع والمهام داخل مؤسسة واحدة. يستهدف مشكلة محتملة لدى الفرق الصغيرة: تشتت بيانات العميل وتحديثات المشروع ومسؤولية التنفيذ. هذا افتراض تصميمي وليس نتيجة مقابلات عملاء. كان الهدف سير عمل صغيرًا مكتملًا بحدود وصول وبيانات واضحة.

## المستخدمون والمتطلبات

يضبط المسؤول المؤسسة والعضويات، وينسّق المدير العملاء والمشاريع والمهام، ويحدّث العضو حالة المهام المسندة إليه. تشمل المتطلبات التهيئة والمصادقة والصلاحيات وعزل المؤسسات والبيانات المترابطة وسجل النشاط والتحكم بلوحة المفاتيح. لم تُنفّذ الفوترة أو الإشعارات أو التكاملات أو الذكاء الاصطناعي.

## الحل وسير العمل

تسجيل حساب ← إنشاء مؤسسة بصلاحية مسؤول ← إضافة حسابات زملاء مسجّلة ← إنشاء عميل ← مشروع مرتبط ← إنشاء مهمة وإسنادها ← للتنفيذ / قيد التنفيذ / مراجعة / مكتملة ← مراجعة النشاط. تعرض لوحة المتابعة أعدادًا من قاعدة البيانات. يتطلب إكمال المشروع إكمال مهامه، وتحافظ الأرشفة على السياق.

## البنية ونموذج البيانات

المتصفح ← Next.js App Router ← وكيل API من النطاق نفسه ← NestJS ← Prisma وPostgreSQL. يفصل المستودع الواجهة والواجهة البرمجية والعقود والصلاحيات وقاعدة البيانات. لا توجد حاجة إلى Redis أو BullMQ.

يرتبط User بـ Organization عبر Membership التي تحمل الدور. تملك المؤسسة Client ثم Project ثم Task. يشير منشئ المهمة والمكلّف بها إلى عضويات ضمن المؤسسة نفسها. تدير RefreshSession الجلسات، وتسجّل AuditEvent الفاعل والتغيير، وتحفظ AuthThrottle عدّادات محاولات المصادقة. تفرض المفاتيح الخارجية المركبة هوية المؤسسة داخل العلاقات.

## الصلاحيات وعزل المؤسسات

تُعرّف القدرات مركزيًا: المسؤول يدير المؤسسة والأعضاء، والمدير يدير العمل، والعضو يقرأ مساحة العمل ويغيّر حالة مهامه المسندة فقط. جميع الأدوار النشطة تقرأ بيانات أعمال المؤسسة؛ لا توجد مشاريع خاصة. يرى المسؤول جميع الأحداث، والمدير أحداث الأعمال، والعضو أحداثه الشخصية. يمنع النظام إزالة آخر مسؤول أو خفض دوره.

معرّف المؤسسة في الرابط ليس إذنًا. يعيد الخادم فحص العضوية والقدرة داخل معاملة تقفل المؤسسة، ويقيّد استعلامات الموارد بها. تُرفض معرّفات الموارد الأجنبية دون كشفها، وتمنع قيود قاعدة البيانات ربط عميل أو مشروع أو مكلّف من مؤسسة أخرى. لا تمنح الواجهة صلاحية بمجرد إظهار زر.

## المصادقة وقرارات الأمان

تُجزّأ كلمات المرور بـ Argon2id. يستمر رمز الوصول عشر دقائق ويرتبط بجلسة نشطة؛ تُحفظ أسرار التجديد كقيم مجزّأة، وتُدوّر مع إبطال عائلة الجلسة عند إعادة الاستخدام. تنتهي الجلسة بعد سبعة أيام كحد مطلق. يدعم النظام الخروج والخروج من جميع الأجهزة.

تُحفظ الرموز في ملفات ارتباط HttpOnly وSameSite، مع Secure في الإنتاج، ولا تظهر في JSON أو التخزين المحلي للمتصفح. تتطلب التعديلات Origin موثوقًا وترويسة مخصصة. توجد حدود لحجم الطلب ومحاولات المصادقة وأخطاء آمنة. لا يُدّعى اعتماد أمني؛ إغلاق التسجيل وحدود العرض التجريبي والتحقق من HTTPS المنشور ما زالت متطلبات قبل الاستضافة.

## سلامة البيانات والتزامن

تنشئ هجرتان SQL العلاقات والفهارس والقيود. تبقى العضوية الملغاة للتاريخ وتصبح مهامها غير مسندة. لا يُحذف عميل مرتبط بمشاريع. تُمنع تعديلات مهام المشاريع المغلقة حتى إعادة فتحها.

يرسل تعديل المهمة إصدارها المقروء؛ يُرفض التحديث القديم بتعارض بدل استبدال عمل مستخدم آخر. تنسّق أقفال المؤسسة تغييرات الصلاحيات مع تعديلات الأعمال، وتسجّل المعاملة التغيير وحدثه معًا. تُنسّق عمليات الجلسة بقفل معاملة لكل مستخدم. هذا اختيار لصحة العمليات في فريق صغير، وليس ادعاء أداء على نطاق واسع.

## تجربة الاستخدام

تنقّل واضح وتفاصيل تربط العميل بمشروعه ومهامه. نماذج وحوارات أصلية تدعم التركيز والتحقق والتأكيد؛ تغيير الحالة متاح بلوحة المفاتيح ولا يعتمد على السحب. تتكيّف الأعمدة مع الهاتف واللوحي وسطح المكتب. تشمل التجربة التحميل والفراغ والأخطاء والتعارض والقراءة فقط. أعداد الأعمدة تخص صفحة النتائج المعروضة ويُذكر ذلك صراحة.

## الاختبار والتحقق

نجح **37 اختبارًا محليًا**: 34 سيناريو تكامل عبر Nest وPostgreSQL الفعليتين وثلاث حالات لإعدادات الإنتاج. تشمل الاختبارات رفض الوصول بين المؤسسات والمراجع الأجنبية وتجاوز الصلاحيات والجلسات الملغاة وإعادة التجديد والتحديثات المتعارضة وآخر مسؤول. تمر بوابات التنسيق والفحص والأنواع والبناء والهجرات وتدقيق التبعيات وفحص النشر.

أكمل المتصفح الفعلي التسجيل والمؤسسة والعميل والمشروع والمهمة والإسناد والحالات والنشاط، مع الأدوار الثلاثة ولوحة المفاتيح واستمرار البيانات بعد التحديث. لقطات الشاشة من تطبيق يعمل ببيانات Northstar الخيالية؛ ليست تصميمًا تصوريًا أو دليل تشغيل منشور.

## التحديات والدروس

تطلّب سباق تغيير الصلاحيات حدود معاملات مشتركة، وتطلّب عزل البيانات تطابق التحقق البرمجي مع القيود المركبة. يجب أن يُحفظ إبطال جلسة التجديد قبل إعادة الخطأ. كشف اختبار تشغيل البناء تبعية Express مباشرة ناقصة، وتم إصلاحها. وكشفت مراجعة الصور قصّ أزرار عنوان مشروع طويل، وتم تصحيح التخطيط.

أثبتت التجربة قيمة الاختبارات السلبية ومصفوفة الصلاحيات المبكرة، وأن نجاح البناء وحده لا يثبت نجاح التشغيل. كما أن عرضًا محليًا مكتملًا يحتاج ضوابط إساءة استخدام وبيانات محدودة واستعادة قبل إتاحته للعامة.

## الحدود والعمل المستقبلي

لوحة المهام مقسمة إلى صفحات من 40 مهمة، ومحددات المراجع مناسبة لفريق صغير. لا توجد استعادة كلمة مرور أو تحقق بريد أو MFA أو دعوات بريدية. قد يفرض تضارب تجديد الجلسة بين تبويبين تسجيل الدخول مجددًا. حدود العرض التجريبي وإعادة الضبط والاحتفاظ والنسخ الاحتياطي والمراقبة والتحقق من الاستضافة ما زالت عملًا مستقبليًا. لا توجد مقاييس أداء إنتاجية أو أرقام عملاء أو ادعاءات تبنٍّ تجاري.
